## Conventions: правила для генерации кода (для code‑assistant)

Источник требований — документ архитектуры и видения: [vision.md](./vision.md). Если в этих правилах что‑то не описано или есть конфликт, приоритет у `vision.md`.

### Базовые принципы
- **Следуй `vision.md`**: технологии, структура, архитектура, модели и интерфейсы — без самодеятельности.
- **KISS, YAGNI**: только необходимое для задачи. Минимум зависимостей и абстракций.
- **Читаемость > хитрость**: код должен быть очевидным для другого разработчика.

### Язык и стиль
- **TypeScript strict** везде; явные типы для публичных API и границ модулей.
- **Именование**: дескриптивные полные имена, без аббревиатур и 1–2‑буквенных переменных.
- **Контроль потока**: ранние возвраты, глубина вложенности ≤ 3, без лишних try/catch.
- **Форматирование/линт**: совместимо с ESLint/Prettier; не отключай правил без причины.

### Архитектура и структура
- **Структура каталогов** — как в `vision.md` (client/server/shared). Не создавай произвольных папок.
- **Разделяй ответственность**: сцены, системы, генераторы, AI — отдельные модули с узкими интерфейсами.
- **Общие типы** в `shared`; никаких дублированных типов между клиентом и сервером.

### Конфигурация и секреты
- **Без хардкода**: параметры и баланс — из конфигов; ключи — из окружения.
- **Типобезопасная конфигурация** с валидацией при старте. Никаких секретов в клиентском бандле.

### Логирование и ошибки
- **Структурные логи** и уровни — как описано в `vision.md`; без `console.log` в проде.
- **Ошибки**: информативные, без утечки PII; добавляй контекст (requestId/seed и т. п.).

### Данные и API
- **Контракты** типизированы end‑to‑end (shared схемы/типовки). Валидация входа/выхода.
- **Миграции** и индексы — следуй моделям из `vision.md`; не расширяй схему без необходимости.

### Тестирование и качество
- **Юнит‑тесты** для новой логики (генерация чанков, AI, подсчёт очков).
- **E2E smoke** при добавлении новых пользовательских сценариев.
- **Zero‑warn build**: линт и типы должны проходить до коммита/PR.

### Производительность (клиент)
- **60 FPS как цель**: избегай аллокаций в игровом цикле, используй пулы объектов.
- **Детерминизм генерации**: учитывай seed и ограничения из `vision.md`.

### Зависимости
- **По умолчанию — стандартные средства**. Новые библиотеки — только при явной выгоде (размер/скорость/поддержка).

### Документация в коде
- **Комментарии только по делу**: объясняй неочевидные решения, инварианты, крайние случаи.
- **JSDoc** для экспортируемых функций/классов публичных API.

### Git/CI (минимум)
- **Малые атомарные изменения**; сообщения и PR соответствуют принятым в репозитории правилам.

См. детали и конкретику в [vision.md](./vision.md). Этот файл задаёт минимальный, практичный набор правил, влияющих на качество кода и поддерживаемость.
