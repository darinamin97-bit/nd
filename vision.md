## Техническое видение проекта «Якобиты против Англичан»

Основано на концепции из [idea.md](./idea.md): 2D side‑scroller (по типу Super Mario) с бесконечной процедурно генерируемой картой, онлайн‑доставка и таблица лидеров, выбор фракции (Якобиты/Англичане), минимум три типа противников.

### Технологии
- **Клиент (браузер)**:
  - TypeScript 5+, Vite (сборка), Phaser 3 (2D‑движок), Phaser Arcade Physics
  - ESLint + Prettier (качество кода), Vitest (юнит‑тесты), Playwright (E2E)
  - PNPM (workspace/monorepo), MSW (моки API в dev)
- **Сервер (API)**:
  - Node.js 20+, Fastify (HTTP), Zod/Joi (валидация), Prisma ORM
  - PostgreSQL (Neon/CloudSQL/RDS), Redis (кэш/рейт‑лимиты) — опционально
  - Pino (структурное логгирование), OpenAPI (спецификация API)
- **Инфраструктура**:
  - CI/CD: GitHub Actions
  - Хостинг клиента: Vercel/Cloudflare Pages/Netlify (статические ассеты + CDN)
  - Хостинг API: Fly.io/Render/Railway (Docker), БД: Neon.tech/Postgres‑as‑a‑Service
  - Observability: Sentry (клиент+сервер), (опц.) OpenTelemetry + Prometheus/Grafana

### Принцип разработки
- Итеративно‑инкрементальный подход: MVP → короткие релизы → метрики → улучшения
- GitFlow (feature ветки) или Trunk‑Based (короткоживущие ветки), Code Review
- Conventional Commits, SemVer релизы, автоматическая генерация CHANGELOG
- Feature flags/конфигурационные переключатели для безопасных релизов
- Обязательные тесты (юнит + e2e smoke) и линт в CI перед деплоем

### Архитектура проекта
- **Клиент**:
  - Сцены: `Boot` (прелоад), `Menu` (выбор фракции), `Game` (игра, переходы между аренами), `GameOver` (результаты)
  - Системы: управление, физика, ИИ врагов, боёвка, генерация чанков, подсчёт очков, коллизии, спавн/деспавн
  - Процедурная генерация: детерминированная (seed) с набором «шаблонов сегментов» + вариации
  - AI: три базовых архетипа (стреляющий/рубящий/ловушка) через конечные автоматы состояний
  - Данные и баланс: конфиг‑файлы, таблицы вероятностей и кривые сложности
- **Сервер**:
  - Лёгкий REST API: `/api/scores` (POST сабмит результата, GET топ), `/api/health`
  - (Опц.) `/api/users` для профилей/авторизации (гостевой режим по умолчанию)
  - Валидация запроса и античит: рейт‑лимиты, подпись результата, базовые эвристики
  - БД: PostgreSQL, миграции Prisma, индексы по времени/счёту

### Модель данных (БД)
- `users` (опционально):
  - `id` UUID (PK)
  - `display_name` TEXT NULL
  - `created_at` TIMESTAMPTZ
- `scores`:
  - `id` UUID (PK)
  - `user_id` UUID NULL (FK → users) — для гостей NULL
  - `faction` ENUM('JACOBITE','ENGLISH')
  - `score_total` INT NOT NULL
  - `distance` INT NOT NULL
  - `enemies_defeated` INT NOT NULL DEFAULT 0
  - `seed` TEXT NOT NULL
  - `meta` JSONB NULL  // версии клиента, сложность, билд
  - `signature` TEXT NULL // античит подпись
  - `created_at` TIMESTAMPTZ
  - Индексы: (`score_total` DESC), (`created_at` DESC)
- (Клиентские runtime‑структуры — не в БД): `MapChunk`, `EnemySpawn`, `Trap`, `ItemDrop`

### Сценарии работы
- **Игрок**: запуск → `Boot` (прелоад) → `Menu` (выбор фракции) → `Game` → генерация арены → бой/платформинг → переход на следующий чанк → смерть/падение → `GameOver` → отправка результата → повтор
- **Сабмит результата**: клиент формирует payload (счёт, дистанция, seed, версия), добавляет подпись → POST `/api/scores` → сервер валидирует и сохраняет → возвращает позицию в рейтинге
- **Просмотр рейтинга**: GET `/api/scores?limit=100` с кэшированием

### Деплой
- **Клиент**: статическая сборка (Vite) → загрузка в Vercel/Cloudflare Pages → CDN кеширование → версионирование ассетов
- **Сервер**: Docker‑образ → Fly.io/Render, переменные окружения → миграции Prisma на старте → авто‑деплой из GitHub Actions
- **БД**: управляемый Postgres (Neon). Миграции в CI перед раскаткой или в entrypoint
- **Секреты**: GitHub Environments/Secrets, без утечек в клиент

### Подход к конфигурированию
- Иерархия: `default` → `env` (development/staging/production) → переменные окружения
- **Клиент**: `import.meta.env.*` (Vite), файл `client/src/config/*`, типобезопасность через Zod
- **Сервер**: `.env` + Zod‑парсинг на старте, обязательные ключи: `DATABASE_URL`, `API_BASE_URL`, `SENTRY_DSN` (опц.), `RATE_LIMIT_*`
- Конфиги геймплея отделены от кода (таблицы/JSON), чтобы облегчить балансировку

### Подход к логгированию
- **Клиент**: уровни `error/warn/info` (выключаем `debug` в prod), отправка ошибок в Sentry, дебаг‑оверлей в dev
- **Сервер**: Pino (JSON), кореляция `requestId/traceId`, логирование входящих запросов/исходов, маскирование PII, ротация на уровне платформы, экспорт в сторонние лог‑хранилища
- Метрики: базовые RPS/latency/error rate; алерты в случае деградации

### Нефункциональные требования
- **Производительность**: 60 FPS на средних ноутбуках/мобильных; атласы спрайтов, lazy‑loading ассетов, пулы объектов; ограничения на количество активных сущностей
- **Размер бандла**: цель < 2–3 МБ gz, code‑splitting сцен
- **Кроссплатформенность**: современные браузеры desktop + mobile; fallbacks для ввода
- **Доступность**: настраиваемые клавиши, визуальные подсказки, режимы для дальтоников (опц.)

### Тестирование и качество
- Юнит‑тесты систем (генерация чанков, ИИ, подсчёт очков)
- E2E smoke (загрузка, выбор фракции, старт/финиш сессии)
- Лоад‑тест API (k6) для сабмита результатов
- Линт и типы обязательны в CI

### Безопасность и античит (минимально жизнеспособный)
- Рейт‑лимиты по IP/пользователю
- Подпись результата (HMAC) с проверкой версии клиента и допустимых диапазонов
- Эвристики: время сессии, недостижимые комбинации параметров
- Осознанное ограничение: строгая защита от читов невозможна на чисто клиентской логике; цель — усложнить тривиальные накрутки

### Путь развития (Roadmap, high‑level)
- MVP: базовые механики, 3 типа врагов, генерация чанков, таблица лидеров
- R1: баланс/контент (больше шаблонов арен, предметы), визуальные улучшения
- R2: сезонные ивенты, скины фракций, расширенная аналитика
- R3: (опц.) кооператив/асинхронные призраки, события/испытания
