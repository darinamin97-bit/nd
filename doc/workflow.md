## Workflow: правила выполнения итераций по тасклисту

Опирайся на: [doc/tasklist.md](./tasklist.md) и архитектурное видение: [vision.md](../vision.md). Если есть расхождения — приоритет у `vision.md`.

### Общие принципы (KISS)
- Работай строго по плану: выполняй следующую незавершённую итерацию из `doc/tasklist.md`.
- Минимум изменений, никаких лишних зависимостей или абстракций. Только то, что нужно для итерации.
- Не отклоняйся от технологий и структуры из `vision.md`.

### Цикл итерации
1) Пред‑согласование
   - Подготовь краткое «Предложение решения» для текущей итерации:
     - цель и краткий объём работ;
     - список затрагиваемых модулей/файлов;
     - ключевые интерфейсы/типы/эндпойнты;
     - короткие отрывки кода (скелеты/сигнатуры/дифф‑фрагменты) для согласования;
     - критерии приёмки и тест‑план (юнит/E2E smoke).
   - Вынеси на согласование. Не приступай к реализации до подтверждения.

2) Реализация
   - Реализуй ровно согласованный объём.
   - Убедись, что сборка, типы и линт проходят; запусти тесты из предложения.
   - Обнови `doc/tasklist.md` для текущей итерации:
     - статус строки в таблице → ⏳ при старте, ✅ после подтверждения;
     - дата и краткий результат (1 строка);
     - отметь чекбоксы завершённых подпунктов задачи.
   - Подготовь «Отчёт итерации»: что добавлено, где смотреть код, как проверить.
   - Запроси подтверждение результата.

3) Завершение и переход
   - После подтверждения: установи ✅ в таблице прогресса, зафиксируй дату/результат.
   - Сделай коммит по Conventional Commits: `feat: iteration <N> - <кратко>` (или `fix:`/`refactor:` по ситуации).
   - Запроси согласование на старт следующей итерации.

### Нормы согласования и кода
- Показывай только релевантные фрагменты кода с достаточным контекстом.
- Не расширяй архитектуру/модель данных/зависимости без ссылки на разделы `vision.md`.
- Конфигурация, секреты, логирование и метрики — строго по `vision.md`.
- Производительность: избегай тяжёлых аллокаций в игровом цикле, следуй целям из `vision.md`.

### Обновление прогресса
- Таблица в `doc/tasklist.md`: иконки статуса (⏳/✅), дата, краткий результат.
- Чекбоксы задач — для наглядности хода работ внутри итерации.

Этот Workflow намеренно краткий. Детали реализации, архитектурные решения и стандарты — в [vision.md](../vision.md).
